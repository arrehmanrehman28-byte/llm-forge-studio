⚙️ TRAINING SETTINGS EXPLAINED - SIMPLE!
================================================================================

SIMPLE SETTINGS (Train Tab):

Epochs: How many times AI reads your data
  1: Fastest demo (5 mins, good for testing)
  2: Good demo (5-10 mins, 79% loss reduction) ⭐ Recommended for first time
  3-5: Better quality (15-30 mins, 85%+ reduction)
  10: Best quality (1 hour+, needs more data)

  For sample data (6 examples): Use 2 epochs
  For your data (100 examples): Use 3-5 epochs

Batch Size: How many examples AI sees at once
  1: Lowest VRAM, slowest, for CPU or 4GB RAM
  2: Low VRAM, for slow computer
  4: Balanced, for T4 GPU (Recommended) ⭐
  8: Faster, needs more VRAM (for A100, RTX 4090)

  If you get CUDA out of memory: Reduce batch size to 2 or 1

Learning Rate: How fast AI learns
  1e-4 (0.0001): Slow but stable, safe
  3e-4 (0.0003): Balanced, Recommended ⭐
  5e-4 (0.0005): Fast, good quality
  1e-3 (0.001): Very fast but risky, may fail

  For first time: Use 3e-4
  If loss doesn't go down: Try 1e-4
  If training too slow: Try 5e-4

ADVANCED SETTINGS (Accordion - Already checked by default! Best!):

✅ DoRA - Weight-Decomposed Low-Rank Adaptation
   What: Better LoRA, decomposes weights
   Benefit: +2-3% quality! Better chatbot responses
   Cost: Slightly more VRAM, worth it!
   Use: Always checked ✅

✅ NEFTune - Noisy Embedding Fine-Tuning
   What: Adds noise to embeddings during training
   Benefit: +2% quality for small data! Prevents overfitting
   Cost: None! Free quality boost
   Use: Always checked for small data (<100 examples) ✅

✅ Packing - Pack multiple examples together
   What: Instead of padding to max length (wastes 50%), pack multiple short examples into one long
   Benefit: 2x faster! 100% data used, 0% wasted! Minimal data loss!
   Cost: None! Always better
   Use: Always checked ✅

✅ Flash Attention - Fast attention implementation
   What: Faster, memory-efficient attention
   Benefit: 1.3x faster, less VRAM
   Cost: Needs newer GPU (T4 works, CPU doesn't)
   Use: Checked for GPU, unchecked for CPU

✅ LoRA+ / RS-LoRA - Better LoRA training
   What: Improved LoRA learning rate and scaling
   Benefit: Better quality, more stable
   Use: Checked ✅

✅ Gradient Checkpointing
   What: Saves VRAM by recomputing instead of storing
   Benefit: Saves 30% VRAM, can train bigger models
   Cost: 20% slower
   Use: Checked if low VRAM (8GB), unchecked if fast GPU

✅ 8-bit Optimizer
   What: Optimizer in 8-bit instead of 32-bit
   Benefit: Saves VRAM
   Use: Checked for low VRAM ✅

Other Advanced:

LoRA Rank (r): Size of LoRA adapters
  8: Smaller, faster, less quality
  16: Balanced (Recommended) ⭐
  32: Bigger, slower, better quality
  64: Biggest, best quality, needs more VRAM

LoRA Alpha: Scaling factor
  32: Default, good with rank 16 (alpha = 2*rank)

Max Steps: Limit training steps
  Leave empty: Train full epochs
  100: For quick demo (100 steps only)

Checkpoint Every: Save progress every N steps
  50: Save every 50 steps (Recommended) - Never lose progress!
  100: Save every 100 steps

Mixed Precision: Training precision
  fp16: For T4, RTX GPUs (Recommended for T4)
  bf16: For A100, better quality
  fp32: For CPU, no quantization

Optimizer:
  adamw_8bit: 8-bit AdamW, saves VRAM (Recommended for 8GB)
  adamw: Standard AdamW, needs more VRAM
  paged_adamw_8bit: Even more VRAM saving

📊 WATCH TRAINING - WHAT TO LOOK FOR
================================================================================

When you click TRAIN MY AI NOW!, you see:

Logs (Text):
  Step 0/100 | Loss: 4.0 | Val: 3.8 | Util: 97% | GPU: 1.7GB
  Step 20/100 | Loss: 2.5 | Val: 2.3 | Util: 98% | GPU: 1.7GB
  Step 40/100 | Loss: 1.2 | Val: 1.0 | Util: 97% | GPU: 1.7GB
  Step 60/100 | Loss: 0.9 | Val: 0.8 | Util: 98% | GPU: 1.7GB
  Step 80/100 | Loss: 0.8 | Val: 0.7 | Util: 97% | GPU: 1.7GB
  🎉 Finished! Loss: 4.0 → 0.8 (Best: 0.7) | 1.7GB VRAM, 1.6x faster!

What it means:
  Step: Current step / Total steps
  Loss: Training loss - Should go down! 4.0 -> 0.8 = Good!
  Val: Validation loss - Should also go down! If goes up = Overfitting
  Util: Data utilization - 97% = Almost all data used, minimal loss!
  GPU: VRAM usage - 1.7GB = 93% saved with QLoRA!

Plot (Graph):
  Blue line: Training loss - Should go down steadily
  Orange line: Validation loss - Should go down with training
  Good: Both lines go down together
  Overfitting: Blue goes down, orange goes up → Need more data or fewer epochs
  Underfitting: Both stay high → Need more epochs or higher lr

GPU Stats:
  VRAM: 1.7GB / 15GB (11% used) - 93% saved!
  Can train 7B on 8GB VRAM ✅

Data Util:
  ✅ 100% Data Used, 0% Lost! (with packing)
  Without packing: 50% wasted on padding!

Status:
  Training... Step 20/100
  Then: 🎉 Finished! Go to Results tab!

GOOD TRAINING SIGNS:
  ✅ Loss goes down: 4.0 -> 0.8 (79% reduction!)
  ✅ Val loss also goes down: 3.8 -> 0.7
  ✅ Both lines in plot go down together
  ✅ Data Util 97%+ (with packing)
  ✅ No CUDA out of memory
  ✅ Finished without errors

BAD TRAINING SIGNS & FIXES:
  ❌ Loss doesn't go down (stays 4.0):
     Fix: Higher learning rate (5e-4), more epochs, check data

  ❌ Loss goes down then up:
     Fix: Lower learning rate (1e-4), fewer epochs

  ❌ Val loss goes up while train goes down (Overfitting):
     Fix: More data, fewer epochs, enable NEFTune, lower lr

  ❌ CUDA out of memory:
     Fix: Batch size 1, enable gradient checkpointing, 8-bit optimizer, QLoRA

  ❌ Data Util low (50%):
     Fix: Enable Packing! Goes to 97%+

  ❌ Very slow:
     Fix: Enable Packing (2x faster), Flash Attention, batch size 8

Method 2: Download checkpoints:

  After training, in Colab:
  !zip -r checkpoints.zip ./checkpoints
  from google.colab import files
  files.download('checkpoints.zip')

Method 3: Push to HuggingFace Hub:

  In Export Tab, check Push to Hub, type username/model, Export
  Now model saved on Hub, can load anytime!

Checkpoint Every 50 Steps:

  In Train Tab, Advanced, Checkpoint Every: 50
  Saves every 50 steps, never lose more than 50 steps!
  If Colab disconnects at step 120, you have checkpoint at 100, resume from 100!

Minimal Data Loss:

  - Packing: 100% data used (vs 50% without)
  - Lossless tokenization: No data lost in tokenization
  - Checkpointing: Never lose progress
  - Drive mount: Save to Drive

🆘 TROUBLESHOOTING TRAINING
================================================================================

Problem: CUDA out of memory
  Fix: Batch size 1, gradient checkpointing ✅, 8-bit optimizer ✅, QLoRA ✅

Problem: Loss doesn't go down
  Fix: Higher lr (5e-4), more epochs, check data format, enable Packing

Problem: Val loss goes up (overfitting)
  Fix: More data, fewer epochs, lower lr, enable NEFTune ✅

Problem: Training too slow
  Fix: Enable Packing (2x faster!) ✅, Flash Attention, batch size 8

Problem: Data Util low (50%)
  Fix: Enable Packing! Goes to 97%+ ✅

Problem: Colab disconnects
  Fix: Mount Drive, checkpoint every 50, download checkpoints

Problem: No Gradio link
  Fix: Runtime -> Restart runtime, rerun all cells, check for errors in logs

Problem: Fallback demo shown instead of full Studio
  Fix: Restart runtime, rerun, check app.py exists, check error in fallback demo
