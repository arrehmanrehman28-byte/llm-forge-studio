STEP 3: TRAIN YOUR AI (Train Tab - 🚀 Step 3: Train Your AI)
--------------------------------------------------------------------------------
Simple Settings (Big Friendly UI):

  Epochs: How many times AI reads your data
    - 1-2: Demo, fast (5 mins for Qwen 0.5B)
    - 3-5: Better quality (10-15 mins)
    - For first time: Use 2

  Batch Size: How many examples at once
    - 4: For T4 GPU (Recommended)
    - 2: If computer is slow or low VRAM
    - 1: For CPU or very low RAM

  Learning Rate: How fast AI learns
    - 1e-4: Slow but stable
    - 3e-4: Balanced (Recommended) ⭐
    - 5e-4: Fast
    - 1e-3: Very fast but risky

Advanced Settings (Accordion - Already checked by default - BEST!):

  ✅ DoRA - Weight-Decomposed Low-Rank Adaptation - +2-3% quality!
  ✅ NEFTune - Noisy Embedding Fine-Tuning - +2% for small data!
  ✅ Packing - Pack multiple examples together - 2x faster, 100% data used, 0% lost!
  ✅ Flash Attention - Faster attention, less VRAM
  ✅ LoRA+ / RS-LoRA - Better LoRA training
  ✅ Gradient Checkpointing - Saves VRAM
  ✅ 8-bit Optimizer - Saves VRAM

  All checked by default = Best quality + fastest + minimal data loss!

  Other Advanced:
  - LoRA Rank: 16 (default, good!)
  - LoRA Alpha: 32 (default)
  - Max Steps: Leave empty for full training
  - Checkpoint Every: 50 steps (saves your progress!)
  - Mixed Precision: fp16 (for GPU) or bf16 (for A100)

If you prefer code over UI, run this in Colab after install:

from backend.trainer import train_model
from backend.efficiency import calculate_efficiency_gains

config = {
    'model_id': 'Qwen/Qwen2-0.5B-Instruct',  # Fastest for T4
    'epochs': 2,
    'batch_size': 4,
    'lr': 2e-4,
    'lora_r': 16,
    'use_lora': True,
    'use_qlora': True,  # 4-bit, 93% VRAM saved!
    'dora': True,      # +2-3% quality
    'neftune': True,   # +2% small data
    'packing': True,   # 2x faster, 100% util
}

eff = calculate_efficiency_gains(config)
print(f"⚡ {eff['vram_usage']} ({eff['vram_saved']} saved), {eff['speed_multiplier']}, {eff['quality_boost']}")
print(f"💾 Can train 7B on {eff['can_train_7b_on']}")

print("\n🚀 Training...")
for update in train_model(config, 'sample_data.csv'):
    if update['step'] % 20 == 0:
        m = update['metrics']
        print(f"Step {m['step']}/{m['total_steps']} | Loss: {m['train_loss']} | Val: {m['val_loss']} | Util: {m['data_utilization']}%")
    if update['finished']:
        print(f"✅ Done! Final loss: {update['metrics']['train_loss']}, Best val: {update['metrics']['best_val_loss']}")
        break

# Results
import json
with open('./checkpoints/results.json') as f:

    print(f"\n📊 Results: {results['loss_reduction']} loss reduction, {results['ppl_reduction']} PPL reduction")
    print(f"Data Utilization: {results['data_utilization']}, Convergence: {results['convergence']}")

💡 TIPS FOR MAKING GOOD MODELS
================================================================================

1. DATA QUALITY > QUANTITY:
   - 100 good examples > 1000 bad examples
   - Clear instruction + good output
   - No duplicates, no empty rows
   - For chatbot: Conversational data
   - For summarization: Article + summary pairs

2. FOR COLAB FREE T4 (15GB VRAM):
   - Use Qwen 0.5B (5 mins) or tiny-10M (10 mins)
   - Batch size 4, epochs 2-3
   - Enable all efficiency: DoRA, NEFTune, Packing (checked by default!)

3. FOR BETTER QUALITY:
   - More epochs (3-5)
   - More data (50-100 examples)
   - Lower learning rate (1e-4)
   - Enable DoRA + NEFTune (+6% quality!)

4. FROM SCRATCH VS FINE-TUNING:
   - Fine-tuning Qwen 0.5B: Fastest, best quality, needs little data (6 examples works!)
   - From Scratch tiny-10M: Learn how LLMs work, no prior knowledge, needs more data

5. SAVE CHECKPOINTS (Important for Colab!):
   from google.colab import drive
   drive.mount('/content/drive')
   # Set output_dir to /content/drive/MyDrive/llm-forge/checkpoints
   # Now checkpoints saved to Drive, not lost when Colab disconnects!

6. AVOID OVERFITTING:
   - If train loss goes down but val loss goes up → Overfitting!
   - Fix: More data, fewer epochs, lower lr, enable NEFTune
   - Good: Both train and val loss go down together

7. VRAM SAVING:
   - QLoRA 4-bit: 93% VRAM saved! (7B model on 8GB VRAM!)
   - Gradient Checkpointing: Saves more VRAM, slower
   - Batch size 1: Lowest VRAM
   - Packing: 2x faster + 100% data used

8. SPEED:
   - Packing: 2x faster!
   - Flash Attention: 1.3x faster
   - Batch size 8: Faster than 4 (if VRAM allows)
   - epochs 1: Fastest demo
